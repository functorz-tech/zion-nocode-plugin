# PRE capability router

Use this router only after `schema load` returned `pre_type_system_refactor`.
Read only the capability files needed for the task. Never read from the sibling variant directory.
A capability absent from this directory is unavailable for this project variant.

## Capabilities

Each capability is a sibling file in this skill folder. When a task calls for one, read that file for its domain rules and `zion-mcp` CLI recipes. Work data-first: build the data model before the UI that displays it and the action flows that mutate it.

- **Project overview & relation graph** (`project-overview.md`) — Bird's-eye views of the whole project — a one-shot inventory of every top-level entity (tables, flows, triggers, APIs, agents, roles, types) and a relation graph around any one entity. The recommended first stop on an unfamiliar app before diving into a domain.
- **Database schema (tables, fields, relations, constraints)** (`schema-table.md`) — Create, modify, or delete database tables, columns, relations, and unique constraints. Use when designing or changing the data model (adding a table, field, relation, or constraint), or when you need column-type rules, naming conventions, or system-table constraints.
- **Data binding** (`data-binding.md`) — Connect a UI component to the data it displays: populate a list or text from a database query, a page or global variable, or the logged-in user; or set a literal constant. Use when an existing component needs live data or a value bound to it, rather than to create or lay out the component itself.
- **UI components & layout** (`ui-component.md`) — Inspect and build the UI component tree and page data. Read tools list pages and return a component's info, its tree context (ancestors/siblings), a container's children, and a component's bindable property slots (each with its ready-to-use binding schemaPath). Write tools create components from type templates, move/reorder them across containers, restyle them (colors, sizes, spacing, text styles), mutate special-component slots (tabs, condition branches, optional slots), wire events to action flows, page navigation, direct database CRUD mutations, and query refreshes, manage page queries/variables/inputs and the app's initial page, and delete subtrees. Data bindings are filled with the bindings plugin's tools at the schemaPaths these tools echo.
- **Action flows (server-side workflows)** (`actionflow.md`) — Inspect and edit server-side action flows: the workflows that run business logic on a button press, a schedule (cron), a database-change event, or a webhook. Use for genuinely multi-step, transactional, or server-only logic such as cross-table writes, trusted calculations, API calls, branching, loops, schedules, and triggers. Do not use merely to wrap simple CRUD when data permissions fully authorize a direct frontend operation.
- **Third-party API configs (TPA)** (`third-party-api.md`) — Inspect and edit Third-Party API (TPA) configs: saved external REST endpoints the app calls from a "Call API" action-flow node or from Run Code. Use to integrate or import an external API — from its online docs or an OpenAPI/Swagger spec — by registering an endpoint (url, method, and query/path/header/body parameters), describing the JSON it returns per success/failure branch, or setting list pagination. Works on every project generation.
- **Project secrets (API keys & tokens)** (`secrets.md`) — Inspect and manage the project's secrets — named references to sensitive values (API keys, tokens) that action flows and API configs use by handle. Use to list available secrets, register a new one, prompt the user to set a value, or rename/retire one.
- **Webhooks (incoming HTTP triggers)** (`webhook.md`) — Create, edit, and inspect webhooks — HTTP endpoints that fire an action flow when called (zed's action-flow Triggers tab). Use to add an incoming webhook, describe its request payload, or enable/disable/delete one.
- **AI agents (ZAI)** (`ai-agent.md`) — Inspect and edit AI agents (ZAI): LLM-backed agents the app runs via a "Run AI" action / action-flow node (async). Use to create or configure an agent's model, temperature, rounds, prompts, typed input arguments, and plain-text or structured output.
- **Runtime logs & debugging** (`runtime-logs.md`) — Fetch and interpret server-side runtime logs. Use when debugging a runtime error, when the user shares a traceId, or when they ask about server logs (covers log types like ACTION_FLOW, GATEWAY, SQL_GENERATION).
- **Web pages & asset import** (`web-assets.md`) — Read public web pages and pull files off the internet into this project. Use it to study a page you are asked to reproduce, to follow reference documentation, and to bring an image, video or file into the project — either as part of the design, for a component to display, or as data, for a media column on a table row.
- **Runtime verification — run it, then check it** (`runtime-verify.md`) — Run and inspect the project's live backend: debug an action flow node by node, read and write table data as admin or as a given user, invoke deployed flows, and clean up afterwards. Use to VERIFY that what you built actually works, as opposed to how it is configured.
- **Permissions (RBAC + ABAC)** (`permissions.md`) — Design and configure RBAC + ABAC access control with tools: activate role permission, create/update/delete roles, and set table/column/row, action-flow, API, AI, and payment permissions. Use when the project involves multiple user groups, data isolation, restricted actions, 403 errors, or table/column/row permissions and relation-first tenant isolation.
- **Payments (WeChat Pay / Alipay)** (`payments.md`) — Design and wire up payments and guide their setup. Use when the project involves checkout, orders, subscriptions, or refunds (covers order-table design, the auto-created payment Actionflows, the webhook idempotency contract, and secure order creation).
- **Sync backend (make edits live)** (`deploy.md`) — Sync the project's running backend with the edited schema ("Sync Backend"). Use after changing the data model, action flows, APIs, permissions, secrets or AI agents, and before anything is tested against the live runtime — until then the backend still serves the previously synced schema.
- **Documentation search** (`docs.md`) — Load when you need general platform guidance, references, or specific step-by-step documentation to query the official Zion developer manual.
- **BaaS runtime — data queries** (`baas-database.md`) — Query & mutate a DEPLOYED project's data over its auto-generated GraphQL API — root operations, the operator-first where grammar, aggregations, and app-user auth. Runtime counterpart to schema-table.
- **BaaS runtime — formula functions** (`baas-formulas.md`) — The runtime GraphQL formula-function catalogue (100+ operand functions) and their enum values, used inside where / order_by operands. Distinct from data-binding UI operators.
- **BaaS runtime — action-flow invocation** (`baas-actionflow.md`) — Invoke server-side action flows from the runtime GraphQL API — sync mutation vs async task + result subscription. Runtime counterpart to actionflow.
- **BaaS runtime — AI agent invocation** (`baas-ai-agent.md`) — Invoke ZAI AI agents from the runtime GraphQL API — create a conversation, stream / structured results, continue / stop. Runtime counterpart to ai-agent.
- **BaaS runtime — binary asset upload** (`baas-assets.md`) — Upload binary assets (image / video / file) to a deployed project via the mandatory presigned-URL + MD5 two-step, then reference them by id.
- **BaaS runtime — third-party API invocation** (`baas-third-party-api.md`) — Invoke a project's imported third-party HTTP APIs from the runtime GraphQL API (operation_<id>, response branching). Runtime counterpart to third-party-api.
- **BaaS runtime — payments** (`baas-payments.md`) — Charge end-users of a deployed project via Alipay / WeChat Pay — server-side order creation, the gateway mutations, and async webhook + idempotent fulfillment. Runtime counterpart to payments.
- **Static site hosting (deploy a built frontend)** (`static-site.md`) — Deploy a frontend you built yourself (a Vite / Next / CRA build output) to the project's hosted static site and get its live url. Use when the user wants to publish, ship, or preview a local build directory, or asks where their site is deployed. Not for pages authored in the Zion editor.
- **WeChat mini program source upload (ship local mini program code)** (`wechat-miniprogram.md`) — Upload a WeChat mini program source tree you developed locally, have Zion commit it to WeChat as the trial version (体验版) under third-party platform authorization, and get the trial QR code. Use when the user wants to ship, preview, or trial-test local mini program code. Stops at the trial version — review and release happen in the Zion editor. Not for the mini program generated from the Zion editor's own pages.

For broad architecture or cross-domain planning, read `platform-overview.md`.
